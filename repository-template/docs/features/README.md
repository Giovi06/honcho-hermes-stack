# Feature and vertical-slice documentation

Create one page per coherent user/business capability when it improves discoverability beyond code and tests. Use short kebab-case filenames and copy [_template.md](_template.md) as the starting point.

Prefer documenting the supported slice end to end: entry points, business rules, data/security boundaries, failures, observability, verification, and related operations. Update an existing page when behavior changes instead of creating a task-specific duplicate.
